# Техническое Задание (ТЗ)

**Проект:** Minecraft Mod Dependency Analyzer & Manager

**Цель:** Создание инструмента для быстрого поиска модов на площадках Modrinth и CurseForge, проверки совместимости версий (Minecraft и Modloader) и автоматического построения дерева зависимостей (dependencies).

---

## 1. Общие требования и архитектура

1. **Тип приложения:** CLI-утилита или легкое GUI-приложение (Electron + Vue 3 + Vite + TypeScript).
2. **Языки разработки:** TypeScript (Node.js/Electron).
3. **Источники данных:**
* **Modrinth API v2** (`[https://api.modrinth.com/v2](https://api.modrinth.com/v2)`) — открытый и бесплатный REST API.
* **CurseForge API v1** (`[https://api.curseforge.com/v1](https://api.curseforge.com/v1)`) — требуется получить бесплатный `x-api-key` в консоли Eternal Developers.



---

## 2. Функциональные требования

### 2.1. Ввод параметров сборки (Контекст)

Перед началом работы пользователь задает базовые фильтры сборки:

* **Версия Minecraft:** (например, `1.20.1`).
* **Загрузчик модов (Modloader):** Выбор из `Forge`, `NeoForge`, `Fabric`, `Quilt`.

### 2.2. Поиск и добавление модов

1. **Поиск по ключу / URL / Slug:**
* Поиск мода по названию или slug (например, `create`, `alexs-mobs`).
* Вставка прямой ссылки на мод с сайта Modrinth или CurseForge.


2. **Определитель платформы:**
* Приложение автоматически определяет, с какой платформы передан мод, и отправляет соответствующий API-запрос.



### 2.3. Рекурсивный анализ зависимостей (Dependency Resolver)

Главная фича приложения — автоматическая сборка «дерева зависимостей»:

1. **Запрос файла мода:** Получение списка доступных файлов под выбpaнную версию игры и модлоадер.
2. **Чтение массива зависимостей:**
* Выявление **Обязательных зависимостей** (Required / Mandatory) — например, библиотечных модов (`Cloth Config`, `Curios API`, `Architectury`).
* Выявление **Опциональных зависимостей** (Optional) и **Несовместимостей** (Incompatible / Incompatibility).


3. **Рекурсивный спуск:** Если найден обязательный библиотечный мод B для мода A, приложение автоматически запрашивает файлы и зависимости для мода B.

### 2.4. Вывод данных и визуал (UI / CLI)

1. **Отображение таблицы / дерева:**
* Название мода + Иконка + Платформа (Modrinth/CurseForge).
* Выбранная версия `.jar` файла.
* Статус зависимостей (например: `[ОК] Все библиотеки найдены` или `[!] Не хватает: Curios API`).


2. **Предупреждения о конфликтах:**
* Выделение красным цветом, если найдены объявленные модом несовместимости.
* Предупреждение, если мод отсутствует под выбранную версию Minecraft (например, есть только на 1.19.2, но нет на 1.20.1).



### 2.5. Экспорт и скачивание

1. **Форматы экспорта:**
* Экспорт списка в **Packwiz format** (`.pw.toml` файлы).
* Экспорт списка в простой файл `mods.txt` (чистые ссылки или slugs).
* Экспорт в JSON-манифест для вашего лаунчера.


2. **Пакетная загрузка:** Кнопка «Скачать все `.jar` в папку», качающая актуальные релизы прямыми HTTP-запросами.

## 3. Требования к API и интеграциям

### Modrinth API Endpoints:

* Поиск: `GET [https://api.modrinth.com/v2/search?query=](https://api.modrinth.com/v2/search?query=){query}&facets=[["categories:{loader}"],["versions:{game_version}"]]`
* Получение версий и зависимостей: `GET [https://api.modrinth.com/v2/project/](https://api.modrinth.com/v2/project/){id_or_slug}/version`

### CurseForge API Endpoints:

* Поиск: `GET [https://api.curseforge.com/v1/mods/search?gameId=432&gameVersion=](https://api.curseforge.com/v1/mods/search?gameId=432&gameVersion=){version}&modLoaderType={type}&searchFilter={query}`
* Получение файлов и зависимостей: `GET [https://api.curseforge.com/v1/mods/](https://api.curseforge.com/v1/mods/){modId}/files`

---

## 4. Этапы и приоритеты разработки (MVP)

* **Этап 1 (MVP):** Парсинг Modrinth API. Ввод `1.20.1 + Forge` + список модов $\rightarrow$ консольный вывод дерева обязательных библиотек.
* **Этап 2:** Подключение CurseForge API и обработка конфликтов/версий.
* **Этап 3:** Графический интерфейс (GUI) или удобный CLI (с табличками `rich` / `cli-table`).
* **Этап 4:** Кнопка автоматического скачивания `.jar` файлов в целевую папку и экспорт в формат лаунчера.
